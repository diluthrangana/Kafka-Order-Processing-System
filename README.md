# Kafka Order Processing System

A production-ready Kafka order message processing pipeline built with Python, featuring Avro serialization, real-time price aggregation (running average), exponential backoff retries for temporary failures, and a Dead Letter Queue (DLQ) for permanent failures.

---

## 1. Requirements Overview (Assignment Compliance)

| Requirement | Implementation |
|---|---|
| **Order Messages** | Generated by `src/producer.py` with `orderId`, `product`, and `price`. |
| **Avro Serialization** | Validated against `schemas/order.avsc` using Schema Registry / Avro serializers. |
| **Real-time Aggregation** | `RunningAverage` calculates running price averages overall and per product on every processed order. |
| **Retry Logic** | Exponential backoff (1s, 2s, 4s up to 3 retries) for temporary processing errors. |
| **Dead Letter Queue (DLQ)** | Permanent failures and exhausted retries are routed to the `orders-dlq` topic with diagnostic headers. |
| **Live Demonstration** | Executable scripts provided for live demo and inspecting DLQ messages. |
| **Git Repository** | Modular structure, version controlled code, `.gitignore`, and documentation. |

## 2. Architecture & Delivery Guarantee

```
                         ┌──────────────────────┐
                         │   Schema Registry    │
                         │   (localhost:8081)   │
                         └──────────▲───────────┘
                    registers/fetches│order.avsc schema
                                      │
┌──────────────┐   Avro bytes   ┌────┴─────┐    poll     ┌──────────────────────────┐
│ producer.py  ├───────────────►│ "orders" ├────────────►│       consumer.py        │
│ (random      │                │  topic   │             │ 1. Deserialize (Avro)    │
│  orders)     │                └──────────┘             │ 2. Validate              │
└──────────────┘                                         │ 3. Process + RETRY       │
                                                         │ 4. Update running avg    │
                                                         │ 5. Commit offset         │
                                                         └────────────┬─────────────┘
                                                                      │ on permanent failure
                                                                      ▼
                                                              ┌──────────────┐     ┌──────────────────┐
                                                              │ "orders-dlq" ├────►│ dlq_consumer.py  │
                                                              │    topic     │     │ (inspect/print)  │
                                                              └──────────────┘     └──────────────────┘
```

### Failure Classification & Handling
1. **Deserialization Errors**: Invalid or corrupt message bytes immediately route to `orders-dlq` with header `dlq.error.type = DESERIALIZATION_ERROR`.
2. **Validation Errors**: Messages violating business constraints (e.g. `price <= 0` or missing fields) route immediately to `orders-dlq` with header `dlq.error.type = VALIDATION_ERROR`.
3. **Temporary Errors**: Simulated downstream service timeouts are retried up to 3 times with exponential backoff (1s -> 2s -> 4s).
4. **Retries Exhausted**: Messages still failing after 3 retries route to `orders-dlq` with header `dlq.error.type = RETRIES_EXHAUSTED`.

### At-Least-Once Processing
Auto-commit is disabled (`enable.auto.commit = False`). The consumer commits the partition offset **synchronously** only after the order is processed successfully or safely written to the DLQ.

## 5. How to Run

### Step 1: Set up Python Virtual Environment
```bash
python -m venv .venv

# Windows:
.venv\Scripts\activate

# Linux/macOS:
source .venv/bin/activate

pip install -r requirements.txt
```

### Step 2: Configure Kafka Broker & Schema Registry
In `src/config.py` (or via environment variables), set your Kafka bootstrap servers and Schema Registry URL:
```python
BOOTSTRAP_SERVERS = os.getenv("BOOTSTRAP_SERVERS", "localhost:9092")
SCHEMA_REGISTRY_URL = os.getenv("SCHEMA_REGISTRY_URL", "http://localhost:8081")
```

### Step 3: Execute Producer & Consumer

Open separate terminal windows:

**Terminal 1 (Consumer):**
```bash
python src/consumer.py --fail-rate 0.3
```

**Terminal 2 (Producer):**
```bash
python src/producer.py --count 10 --interval 1.0 --invalid-rate 0.2
```

**Terminal 3 (DLQ Inspector):**
```bash
python src/dlq_consumer.py
```

**Terminal 4 (Send Corrupt Message Test):**
```bash
python src/send_bad_message.py
```

## 6. Verification & Test Suite

| Test Case | Command | Description |
|---|---|---|
| **Normal Flow** | `python src/producer.py --count 10 --invalid-rate 0` | All orders processed; running average updates in real time. |
| **Exponential Retry** | `python src/consumer.py --fail-rate 0.4` | Retries temporary failures 3 times (1s, 2s, 4s) before succeeding or sending to DLQ. |
| **Validation DLQ** | `python src/producer.py --count 5 --invalid-rate 0.5` | Negative price orders sent straight to DLQ without retry. |
| **Bad Bytes DLQ** | `python src/send_bad_message.py` | Non-Avro raw string sent to `orders`, routed immediately to DLQ as `DESERIALIZATION_ERROR`. |
| **DLQ Inspection** | `python src/dlq_consumer.py` | Displays failed payloads along with headers (`dlq.error.type`, `dlq.original.offset`, etc.). |
